## 一、文章正文格式

正文存的是**原生 HTML**，**不是 Markdown**。前端直接 `innerHTML` 渲染。

### 基本骨架

```html
<section>
<h2>一、开场：从某个具体现象说起</h2>
<p>第一段。用一个读者熟悉的场景或疑问切入，引出本文要回答的核心问题。</p>
<p>第二段。说明这篇文章会讲什么、为什么值得读。</p>

<h2>二、第一个知识点</h2>
<p>...</p>
<p>...</p>

<!-- 按需插入数学公式 / 图表 / 代码 -->
<h2>三、...</h2>
<p>...</p>

<h2>九、小结</h2>
<p>收束全文，点出最值得记住的一两条。</p>
</section>
```

### 硬性要求

| 项目 | 要求 |
|---|---|
| 外层 | 必须用 `<section>` 包裹（现有文章 100% 如此） |
| 分节 | 用 `<h2>`，序号用**中文数字**：`一、二、三…九` |
| 段落 | 用 `<p>`，**不要用 `<br>` 手动换行** |
| 小节数 | **8~9 个 `<h2>`**（实测样本都是 8 或 9 节） |
| 段落数 | 每节 2~4 段 |
| 总字数 | **4500~7000 字**（纯文本，不含标签） |
| 每段长度 | 150~400 字，**要成篇的论述，不要要点列表** |
| 语言 | 简体中文，术语保留原文（如 Docker、CI/CD、KKT） |

### 写法风格（从现有文章提炼）

1. **每篇开头都有「从某个具体现象说起」的引入**，而不是直接下定义。
   实测样本的第一节标题：
   - 「一、从"本地能跑"到"线上可用"」
   - 「一、从"在我机器上是好的"说起」
   - 「一、从"预测历史的数学"说起」
   - 「一、为什么机器学习离不开凸优化」
2. **论述型段落，不是列表**。宁可写成连贯的两三句话，也不要用 `-` 列要点。
3. **有来龙去脉**：讲一个技术/概念时，常从它的历史演进讲起（第一代 → 第二代 → 第三代）。
4. **口语化但不随便**：会用「说白了」「这大概是……」这类自然表达，但整体是书面语。
5. **最后一节做收束**，不是罗列要点，而是给一个判断或展望。

## 二、标题命名

**格式**：`分类名（中文序号）：副标题`

实例：

```
软件工程（八）：CI/CD 流水线——从持续集成到自动部署
Python 学习（三）：FastAPI 快速上手——现代 Web 开发
机器学习数学（十）：凸优化理论——对偶、KKT 与次梯度
科幻文学（四）：阿西莫夫《基地》——心理史学的宏大预言
全栈开发（三）：前后端分离与部署上线实战
```

规则：

- 序号用**中文数字**，且**接着已有文章往下排**（这就是必须先查 `list_posts` 的原因）
- 副标题用 `：` 分隔；需要补一层说明时用 `——`
- 书名用 `《》`，如 `阿西莫夫《基地》`

## 四、摘要（excerpt）

- 长度：**80~150 字**
- 写法：直接截取正文第一段的前一两句即可（现有文章都是这么做的）
- 不要写「本文介绍了……」这种空话，直接进入内容

## 七、发布

### 用脚本（推荐）

```bash
node tools/publish-post.mjs 文章.html \
  --title "软件工程（九）：xxx" \
  --category 软件工程 \
  --excerpt "一句话摘要" \
  --tags "软件工程,CI/CD"
```

脚本会自动：
1. 读 `.mcp-token` 拿管理员 JWT
2. 按分类 slug + 序号自动生成 slug
3. 调 `create_post` 发布
4. 打印文章链接

`--dry-run` 只预览不提交；`--draft` 存草稿不发布。

### 用 MCP 接口（Agent 直接调）

```bash
curl -X POST "$API/api/mcp/invoke" \
  -H "Authorization: Bearer $ADMIN_JWT" -H 'Content-Type: application/json' \
  -d '{"tool":"create_post","arguments":{
        "title":"软件工程（九）：xxx",
        "content":"<section>...</section>",
        "slug":"software-engineering-09-xxx",
        "excerpt":"...",
        "status":"published",
        "is_public":true
      }}'
```

## 十、常见错误

| 错误 | 正确做法 |
|---|---|
| 用 Markdown（`##`、`**`、`- `） | 用 HTML（`<h2>`、`<strong>`、`<p>`） |
| 序号从头开始（写成「（一）」但已有八篇） | 先查 `list_posts`，接着往下排 |
| 用阿拉伯数字分节（`<h2>1. xxx</h2>`） | 用中文数字（`<h2>一、xxx</h2>`） |
| 正文只有几百字 | 4500~7000 字，8~9 节 |
| 写成要点列表 | 写成连贯段落 |
| slug 用中文或空格 | 英文小写 + 连字符 |
| 造新标签（如「AI」） | 复用已有标签（「人工智能」） |
| 忘了 `<section>` 包裹 | 必须包 |

# 02 · 页面与交互体验清单（逐页）

> **这份文档解决什么**：一页一页地告诉站长"这个页面现在什么样、哪里别扭、怎么改、值不值得改"。
> 每条都带**文件路径 + 优先级（P0/P1/P2）+ 工作量（小 <2h / 中 半天 / 大 1天+）**，
> 可以直接照着派活。
>
> **页面清单以 `frontend/src/app.jsx` 的实际路由为准**（2026-10-10 核对）。
> 已删除的模块**不列入**：RSS（`/rss`、`/rss/articles` 已整体删除）、视频页（`/videos` 已改为重定向到首页）。
> 详见 `docs/removed-features.md`。
>
> **重要提醒**：`docs/pages-audit-2026-10-07.md` 是 10-07 写的，部分结论已过时
> （它还在讲 RSS、视频页、博客画廊/时间流切换、`vod-head`/`music-head`）。**以本文为准**。

# 一、公共页

### 首页（未登录落地页 / 已登录控制台） · `/` · `frontend/src/routes/Home.jsx`（337 行）

- **现状**：同一个文件承担两种完全不同的页面——未登录时是营销落地页
  （Hero + 玻璃预览窗 + 功能矩阵 + 能力列表 + 四步 + CTA + 页脚）；已登录时切成"控制台概览"
  （欢迎区 + 4 个模块磁贴 + 最近添加 + 快捷入口），由 `Home()` 里 `if (isAuthenticated) return <Dashboard />` 决定。
- **问题（按严重度排序）**：
  1. **文案与现状不符，且不止一处**：`FEATURES` 里仍有"学习视频库"（视频页已下线）；
     `CAPABILITIES` 里写着"浅色 / 暗色切换"（暗色主题 10-09 已移除，现在是白天 / 素雅）；
     Hero 规格条写"**6** 资源模块"（`FEATURES` 只有 5 项、`MODULES` 只有 4 项）；
     Hero 规格条写"**双视图** 画廊 / 时间流"（`/posts` 已改固定 cosolar 布局，博客不再有双视图）。
     **这四条是访客第一眼看到的内容，错得最显眼。**
  2. **规格条是硬编码数字**，与真实数据无关（"6 资源模块 / 5 重型渲染引擎"）。
  3. Hero 的玻璃预览窗里硬编码了一个具体域名，换域名后不会跟着变。
  4. 落地页与控制台挤在一个 337 行文件里，改一处要读全文；两者信息架构毫无共同点。
  5. 控制台"最近添加"里 GitHub 的跳转目标是列表页而非具体仓库（`MODULES` 里 `github.detail` 固定返回 `/github`）。
- **建议**：
  1. 先改文案（成本极低、收益极高）：删"学习视频库"、把"暗色"改成"素雅"、
     规格条数字改成真实值或改为不带数字的说法（如"多模块 / 多引擎 / 多视图"）。
  2. 把 `Home.jsx` 拆成两个文件：`routes/Home.jsx`（只负责按登录态分发）+
     `routes/landing/` 与 `routes/dashboard/` 两组组件（可先只拆组件、不动路由，风险最小）。
  3. 规格条改为从真实接口取数（复用控制台已有的 `MODULES` 并发请求结果），失败时隐藏而不是显示假数字。
  4. 预览窗的域名改为运行时读取（`window.location.host`）。
- **优先级**：**P0**（文案）／**P1**（拆分与真实数据）
- **工作量**：小（文案）／中（拆分）

### 登录页 · `/login` · `frontend/src/routes/Login.jsx`（55 行）

- **现状**：`<section class="stack login-page" style="max-width:380px;margin:40px auto">`，
  邮箱 + 密码 + 登录/注册切换，错误用 `.notice danger` 显示。
- **问题（按严重度排序）**：
  1. **与全站视觉脱节**：没有品牌标识、没有玻璃卡片包裹，是一张"裸表单"，和落地页的精致感落差明显。
  2. 尺寸全靠行内 `style`，与 `--content-read` 等令牌无关。
  3. 无"忘记密码"入口；注册成功后只提示"请查收邮件"，没有回到登录态的引导。
  4. 顶部没有任何"返回首页"入口（访客误入后只能用浏览器后退）。
  5. 访客模式下顶栏已不显示"登录"按钮，此页**只能靠直接输入网址进入**——应说明这是有意设计，并在页脚或文档标注。
- **建议**：
  1. 用 `.card--pad` 包裹表单 + 顶部放 `Logo`；宽度改用 `--content-read` 或新增 `--auth-width: 420px` 令牌。
  2. 补"忘记密码"（走 Supabase 的 reset 邮件）与"返回首页"。
  3. 错误提示改为 `.field-error`（贴在字段下方），而不是整块 `.notice`。
  4. 用 `PageHeader variant="bare"` 统一标题层级。
- **优先级**：**P1**
- **工作量**：小

### 全局搜索 · `/search` · `frontend/src/routes/Search.jsx`（106 行）

- **现状**：`PageHeader` + `.toolbar`（关键词 + 类型下拉 + 资源类型下拉）+ 结果用 `.gallery-grid` 手拼 `Card`。
- **问题（按严重度排序）**：
  1. **点视频类型的结果会跳到已删除的 `/videos`**（`open()` 里 `else if (item.type === 'video') route('/videos')`），
     用户会被静默重定向回首页，看起来像"点了没反应"。
  2. 点 GitHub 结果一律跳 `/github` 列表页，**不定位到具体仓库**（没有高亮或锚点）。
  3. 结果卡片信息太薄：只有标题 + 摘要 + 类型徽章，**没有高亮命中的关键词**，也没有"来自哪个模块"的更多线索。
  4. 无搜索历史、无最近搜索词、无"结果为空时给建议词"。
  5. 每次搜索都要点按钮或回车，**输入时无即时反馈**（无防抖即时搜索，也无 loading 骨架，只有按钮文案变"搜索中…"）。
  6. `useEffect(() => { if (initialQ) run(initialQ); }, [])` 只在挂载时跑一次，从顶栏搜索框带参进入后**再改 URL 参数不会重新搜**。
- **建议**：
  1. **先修死路由**：视频类型结果改为打开原始链接（`item.url`）或跳 `/movies`，绝不能跳 `/videos`。
  2. GitHub 结果带上 `?q=<仓库名>` 或锚点，落到具体卡片。
  3. 结果卡片加命中词高亮（`<mark>`，只高亮标题与摘要）。
  4. 加"最近搜索"（localStorage，最多 8 条）与空结果推荐词。
  5. 输入防抖 300ms 即时搜索 + `LoadingState shape="list"`。
  6. 用 `useEffect(..., [initialQ])` 让 URL 参数变化能触发搜索。
- **优先级**：**P0**（死路由）／**P1**（高亮、历史）
- **工作量**：小（死路由）／中（高亮 + 历史 + 即时搜索）

### 关联图谱 · `/graph` · `frontend/src/routes/Graph.jsx`（413 行）+ `components/GraphView.jsx`（125 行）

- **现状**：两种视图——默认"控制台"（`.gc-hud` 顶栏 + 流动管线图 + 四块仪表盘，**深色固定，不跟随主题**，每 60 秒轮询）；
  切到"经典视图"是 D3 力导向图（D3 懒加载）。未登录时控制台显示 `EmptyState`（"图谱控制台需要站长登录"）。
- **问题（按严重度排序）**：
  1. **页面没有页头**：`.gc-hud` 自成一套，与全站 `PageHeader` 体系割裂；访客第一次进来没有"这是什么页面"的说明。
  2. **深色固定不跟随主题**：白天/素雅主题下进入图谱会突然变黑，视觉断裂（这是该页刻意的仪表盘风格，但**没有任何过渡或说明**）。
  3. 经典视图的 `onPick` 里仍有 `video: '/videos'` 死路由（点"视频"来源会跳回首页）。
  4. 经典视图**没有图例**：节点颜色（博客/标签/影视/音乐/GitHub）靠猜；无筛选、无搜索节点。
  5. 经典视图加载中只有 `<p class="gc-mute">加载中…</p>` 纯文本。
  6. 控制台每 60 秒全量刷新，切走页面后 `document.hidden` 会暂停（好），但**无"数据更新了"的提示**。
- **建议**：
  1. 页面顶部补一条轻量标题带（标题 + 一句说明 + 视图切换），控制台主体保持深色但**在进入时给一次渐变过渡**，并注明"此页为深色仪表盘"。
  2. 修掉 `video: '/videos'` 死路由。
  3. 经典视图补图例（颜色 + 类型）与节点搜索；加载态换 `LoadingState`。
  4. 控制台刷新后若数据有变化，用一次轻提示（toast）告知。
- **优先级**：**P1**（页头、死路由、图例）
- **工作量**：中

### 实时热榜 · `/news` · `frontend/src/routes/News.jsx`（113 行）

- **现状**：`PageHeader`（带栏目标签栏）+ `.news-grid`，每个热榜源一张玻璃卡，**独立加载、独立刷新**，失败只影响该卡。
- **问题（按严重度排序）**：
  1. 单个源失败时只在卡内显示一行灰字错误，**没有重试按钮**（只有右上角刷新图标，容易被忽略）。
  2. 整页首次加载时是"每张卡各自转圈"，**没有整页骨架**，首屏观感是碎块式加载。
  3. 榜单条目全部 `target="_blank"` 跳外站，**没有站内阅读**（这符合热榜定位，但缺"稍后读/收藏"入口）。
  4. 每张卡的行高、字号是局部规则（`.news-skeleton` / `.news-info`），未走令牌。
  5. `timeAgo` 只有"分钟/小时"，超过一天仍显示"x 小时前"（如"52 小时前"），可读性差。
- **建议**：
  1. 失败卡加显式"重试"按钮（复用 `ErrorState` 的 `onRetry`）。
  2. 首屏用 `LoadingState shape="list"` 统一占位，卡片内再用行骨架。
  3. 条目行加"收藏"图标（走现有 `favorites` 接口）。
  4. `timeAgo` 补"x 天前"。
- **优先级**：**P1**（重试、时间显示）／**P2**（收藏）
- **工作量**：小

### GitHub 收藏 · `/github` · `frontend/src/routes/Github.jsx`（251 行）

- **现状**：左栏（应用分类 + 编程语言方框，sticky 可滚动）+ 右侧（搜索卡 → 工具条 → 仓库卡片列表 + 分页 30 条/页）。
  管理员打开时有未解读仓库会自动连续调用 AI 解读；有"立即同步"按钮。
- **问题（按严重度排序）**：
  1. **页面没有页头**：直接进入两栏，缺少标题与全局读数（共多少个、已解读多少个、上次同步时间）。
  2. **AI 解读的运行状态只在工具条里一行文字**，跑到一半切页/刷新会中断，用户不知道"到底解读到哪了"。
  3. "立即同步"会**删除 GitHub 上已取消 Star 的记录**（`docs/removed-features.md` 已注明），
     但页面上**没有二次确认**，点下去直接开始。
  4. 分页只有"上一页/下一页"文字，无页码，长列表回跳困难。
  5. 左栏在 ≤1000px 变一栏后，语言方框会排在仓库列表**前面**，用户要滑过整个分类区才能看到内容。
- **建议**：
  1. 顶部加 `PageHeader variant="list"`：标题"GitHub 收藏" + 读数条（总数 / 已解读 / 待解读）+ 右侧同步按钮。
  2. AI 解读进度改为可恢复的进度条（已解读/总数），并明确"离开页面会暂停"。
  3. 同步加二次确认，明确写出"会删除已取消 Star 的条目"。
  4. 分页补页码或"跳转到第 N 页"。
  5. ≤1000px 时左栏改为可折叠抽屉（默认收起）。
- **优先级**：**P1**（页头、同步确认）／**P2**（分页、左栏折叠）
- **工作量**：中

### 404 页 · 任意未匹配路径 · `frontend/src/app.jsx` 中的 `NotFound`

- **现状**：`EmptyState`（"页面不存在"）+ 一个"返回首页"按钮。
- **问题（按严重度排序）**：
  1. 只有"返回首页"一条路，**没有"去搜索"**，用户找不到东西时无法自救。
  2. 没有显示用户输入的路径，无法判断是自己打错还是链接过期。
  3. 没有页头，视觉上是一块孤立的空态。
  4. 全站**没有页面标题（`document.title`）**，404 页浏览器标签仍显示站名——所有页面都如此，属于全站问题（见末节）。
- **建议**：补 `PageHeader variant="bare"` + 显示当前路径 + "返回首页 / 去搜索"双按钮；
  同时在全站加"路由切换时更新 `document.title`"（在 `Layout.jsx` 或路由层做一次即可）。
- **优先级**：**P1**
- **工作量**：小

# 二、博客模块

### 博客首页 · `/posts` · `frontend/src/routes/Posts.jsx`（288 行）

- **现状**：cosolar 风格固定布局（2026-10-09 改版）：顶部高清横幅（大搜索框 + 分类/标签/归档入口）→
  精选轮播（最新 5 篇，6 秒自动切换）→ 文章卡片列表（最新/最早切换 + 分页 10 条/页）+ 右侧栏
  （博主卡 / 热门标签 / 专题类别 / 近期更新）。**已无画廊/时间流切换**。
- **问题（按严重度排序）**：
  1. **横幅自动轮播 + 精选轮播两个定时器同时跑**，且横幅目前只有 1 张图（`BANNERS` 长度 1 时定时器不启动，
     逻辑正确），但**精选轮播在"最新 5 篇"里循环，与下方"最新文章"列表内容重复**，观感像卡住了。
  2. 顶部横幅背景图是硬编码的默认图（`BANNERS = [BANNER_HD]`），站长想换自己的素材要改代码
     （`docs/progress.md` 已登记该待办）。
  3. 移动端底部工具栏 `cs-dock`（`.cs-dock`，≤768px）与全局 `MiniPlayer` 会同时出现，
     靠 `body:has(.mini-player) .cs-dock { bottom: 84px }` 硬撑，小屏上页面可用高度被吃掉很多。
  4. 侧栏在 ≤1000px 变单栏后排在列表**下方**，正常；但"博主卡"信息是硬编码（"Dora / 记录技术成长…"）。
  5. 文章卡片删除用 `window.confirm`（原生弹窗），与全站玻璃风格不一致。
  6. `useBlogData` 拉全量文章后在前端筛选/分页，文章变多后会变慢（属性能问题，暂不阻塞）。
- **建议**：
  1. 精选轮播改为"最新 5 篇"中**排除已展示在首屏的**，或干脆改为站长手动指定的精选（加一个 `featured` 字段）。
  2. 横幅素材做成可配置（先支持把图片放进 `frontend/public/blog/` 并改数组，后续可做成设置项）。
  3. 小屏下二选一：进博客页时把 `MiniPlayer` 收成极简条，或把 `cs-dock` 改为可收起。
  4. 博主卡文案改为可配置（或读站点设置）。
  5. 删除确认改用统一确认弹窗组件（与 `AdminUsers` 的危险操作共用）。
- **优先级**：**P0**（移动端底部双条）／**P1**（轮播去重、素材可配置）
- **工作量**：中

### 文章阅读页 · `/posts/:id` · `frontend/src/routes/PostView.jsx`（227 行）

- **现状**：全站**最完整的阅读体验**之一——顶部渐变阅读进度条（`.pv-progress`）、封面头图（`.pv-hero`）、
  桌面端右侧悬浮目录（滚动高亮）、移动端目录抽屉、图片点击放大（缩放/拖动/ESC）、关联资源区。
- **问题（按严重度排序）**：
  1. **没有"上一篇 / 下一篇"**，读完只能返回列表（列表页有 10 条/页，很容易迷路）。
  2. **没有字号 / 行宽调节**，长文阅读体验无法按个人习惯调整。
  3. 阅读进度条用 `z-index: 9999`（魔法数字），且**只在滚动超过 3% 时才出现"回到顶部"**，逻辑分散在行内 style 里。
  4. 头图在无封面时用统一横幅（好），但**头图与正文之间的间距在窄屏被压缩**，标题容易贴住头图。
  5. 目录（TOC）依赖正文标题结构，**无标题的文章没有任何提示**（`pv-layout` 加 `no-toc` 类，但用户不知道"为什么没有目录"）。
  6. `document.title` 不随文章变化（全站问题）。
- **建议**：
  1. 底部加"上一篇 / 下一篇"（`api.listPosts()` 已有全量数据，可直接算）。
  2. 右上角加阅读设置（字号 3 档 + 行宽 2 档，localStorage 记忆）。
  3. 进度条 `z-index` 改用 `--z-progress`；"回到顶部"按钮的显示阈值与进度条统一。
  4. 无目录时给一句提示或隐藏目录区（不要留一个空 aside）。
- **优先级**：**P1**（上下篇、阅读设置）／**P2**（细节）
- **工作量**：中

  1. **分类是"管理型数据"，提供画廊/时间流切换没有意义**（两者渲染几乎一样，只是加了时间轴）。
  2. **不能重命名、不能编辑描述**，只能删除（删除用 `window.confirm`）。
  3. **不显示"该分类下有多少资源 / 文章"**，站长无法判断哪些分类是空的。
  4. 无排序、无搜索（分类多了要翻）。
  5. 删除分类前**不提示会影响哪些内容**。
- **建议**：
  1. 去掉 `ViewSwitch`，改为紧凑表格 / 列表（名称 + 描述 + 资源数 + 操作）。
  2. 支持行内重命名与描述编辑。
  3. 显示使用量，并提供"空分类"筛选。
  4. 删除前提示"该分类下有 N 篇内容，删除后这些内容将变为未分类"。
- **优先级**：**P0**（去掉无意义双视图）／**P1**（编辑、使用量）
- **工作量**：中

### 备份 · `/backup` · `frontend/src/routes/Backup.jsx`（80 行）

- **问题（按严重度排序）**：
  1. **导入前没有预览**：选完文件直接执行，用户不知道文件里有什么、会影响什么。
  2. **导入没有二次确认**（虽有"安全合并"说明，但仍是"点一下就开始写库"）。
  3. 无历史导出记录（不知道上次导出是什么时候）。
  4. 导入结果是**一长串数字挤在一行**（分类/标签/资源/博客/音乐/影视/进度/通知/收藏），可读性差。
  5. 导入是逐条写入（`docs/progress.md` 已登记"非事务、大批量慢"），页面上**没有进度反馈**。
- **建议**：
  1. 选文件后先解析并显示预览（各类条目数量 + 文件生成时间），确认后再导入。
  2. 导入加二次确认弹窗，写明"将与现有数据合并"。

  4. 加导入进度条（后端若支持进度事件则接，否则至少显示"正在处理…"并禁用按钮）。
  5. 记录最近 3 次导出时间（localStorage）。
- **优先级**：**P1**（预览、确认）／**P2**（历史、进度）
- **工作量**：中

- **工作量**：中（UI 骨架）／大（若接后端）

# 八、全站一致性问题汇总（跨页面共性问题，一次说清）

> 这些不是某一页的问题，而是"改一次受益十几页"的共性问题。详细方案见 `docs/improvement/01`。

### 8.1 页头六套并存

`PageHeader`（12 页）/ cosolar 体系（博客 3 页）/ `detail-hero`（影视详情）/ `song-bar`+`song-hero`（音乐详情）/
`np-bar`（音乐沉浸 2 页）/ `pv-hero`（博客阅读）/ `.gc-hud`（图谱）/ `.toolbar`+裸 `<h2>`（3 个编辑页）/
裸 `<h1>`（登录）。**同一个"列表页"从博客跳到音乐再跳到 GitHub，头部结构都会变。**
→ 统一到 `PageHeader` 的三种 variant（`list` / `detail` / `bare`）。

### 8.2 卡片十种写法

`.card`（通用）/ `.cs-card` + `.cs-hero-card`（博客）/ `.gh-card`（GitHub）/ `VodPoster`（影视）/
`.album-card`（音乐）/ `.result-*`（音乐搜索行）/ `.news-card`（热榜）/ `.sh-summary-card`（源健康）/
`.feature-card`+`.cap-card`+`.step-card`（首页）/ `.gc-card`（图谱）。
**元信息行（日期/来源/状态/标签）在每页重复实现。**
→ 补 `.card--pad` / `.meta-row` / `.chip-row`，通用卡一律复用。

### 8.3 加载态与空态四种写法

组件化 `LoadingState`/`EmptyState`/`ErrorState`（主流，20 / 16 / 14 个文件）+
裸文本 `center-box`（`app.jsx` 两处）+ 各页 `<p class="muted">`（`MusicLyrics`、`Graph`、`News`）。
→ `StateView` 是唯一出口；空态必须有 `action`。

### 8.4 行内 `style=` 137 处

集中在 `PostEdit`(24) / `NotificationBell`(15) / `MovieEdit`(14) / `MusicEdit`(9) / `AdminUsers`(9) /
`GraphView`(7) / `Graph`(6) / `Backup`(6) / `ThemeCustomizer`(6)。
**同一张卡片内边距在四个页面写了四种值（12/14/16/18px）。**
→ 补基础类后逐文件替换。

### 8.5 设计令牌几乎没被使用

`--sp-*` 全文件只用 24 次，硬编码 `font-size` 有 245 处；18 种响应式断点表达 5 件事；
`z-index` 混用令牌与 `9999`/`500`/`400`/`150`。
→ 补齐令牌 + 基础类 + 5 个官方断点 + 统一 z 层级。

### 8.6 原生 `confirm` 弹窗

7 处 `window.confirm`（`Posts`、`Tags`、`Categories`、`Music`、`Favorites`、`Videos`），
与全站玻璃风格不一致，且**不能撤销、不能带格式说明**。
→ 统一确认弹窗组件（支持危险色 + 后果说明 + 可选撤销）。

### 8.7 反馈方式不统一

同一件事（保存成功、失败、被拒）在不同页面分别用：`toast`（`Music`/`Movies`/`MovieView`/`SourceHealth`）、
行内 `.notice`（`Backup`/`Login`/`AdminUsers`/`Tags`/`Categories`/`Search`）、
`<p style="color:var(--primary)">`（`Backup`/`AdminUsers`）、以及**静默失败**。
→ 定规则：**一次性操作结果用 toast；需要用户修正的表单错误用 `.field-error`；需要用户阅读的说明用 `.notice`。**

### 8.8 死路由残留

两处指向已删除的 `/videos`：`routes/Search.jsx` 的 `open()`、`routes/Graph.jsx` 的 `onPick`。
用户点了会静默回到首页。→ **P0，必须修**。

### 8.9 全站没有页面标题

`document.title` 从不更新，浏览器标签永远显示"个人知识管理平台"。
多标签用户无法区分页面，分享链接的预览标题也永远是首页标题。
→ 在 `Layout.jsx` 或路由层统一按路由设置标题（P1，小）。

### 8.10 文案与现状不符（多处）

| 位置 | 过时内容 |
| --- | --- |
| `routes/Home.jsx` `FEATURES` | 仍有"学习视频库"（模块已下线） |
| `routes/Home.jsx` `CAPABILITIES` | 写"浅色 / 暗色切换"（暗色已移除，现为白天 / 素雅） |
| `routes/Home.jsx` Hero 规格条 | "6 资源模块"（实际 5 项功能 / 4 个模块磁贴）、"双视图 画廊 / 时间流"（博客已无此功能） |
| `routes/Movies.jsx` 页头副标题 | "12 个采集源"（实际 7 个） |
| `frontend/index.html` meta description | 仍写"RSS 订阅" |
| `docs/frontend.md` | 仍写"主题 light/dark 两套"、"双视图 gallery/timeline"、"Videos.jsx"（均过时，属文档问题） |

→ 一次性文案清查（P0，小），成本极低但直接决定"网站是不是个成熟产品"的第一印象。

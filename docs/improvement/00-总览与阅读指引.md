# Dora Studio 改进建议总览

> **这个文件夹是干什么的**：把 Dora（未来的 Dora Studio）从"能跑"提升到"好用、好维护、
> 好扩展"的**完整改进建议**。不是零散吐槽，而是**可以直接派给执行 Agent 的施工图**。
>
> **写于**：2026-10-10 · **基线版本**：`main` @ `f4d4af8`（影音源修复已上线）
> **面向读者**：站长本人（不懂技术也能看懂结论）+ 后续接手的执行 Agent（照文档就能干活）

---

## 1. 先看这一页：现在是什么水平

### 1.1 已经做得很好的部分（不要推翻）

| 方面 | 现状 |
| --- | --- |
| 基础设施 | 前后端分离、Cloudflare Pages + Workers、Supabase、R2、GitHub Actions 自动部署，全免费额度内 |
| 安全 | 密钥不入库（扫描 82 个提交零泄漏）、访客/登录/管理员三层权限、博客 XSS 清洗、CSP 安全头 |
| 数据完整性 | 写操作强制 `user_id` 隔离、数据库变更走迁移文件、RLS 策略 |
| 影音源 | 影视 7 源**全部实测可用**；音乐 4 源可用 + 3 源如实标注降级；源健康中心可观测 |
| 质量闸门 | 后端 60 项离线测试、前端构建检查、CI 自动跑 |
| 视觉 | 已有自己的"液态玻璃"设计语言，`MovieView` 是全站视觉标杆 |

**结论**：这不是一个需要推倒重来的项目。它需要的是**收敛一致性 + 补齐半成品 + 建立规范**。

### 1.2 三个最核心的问题（一句话版）

1. **一致性缺失**：同一个"页头"有三套写法、同一个"卡片"每页各写各的、编辑页三胞胎、
   加载态四种写法。改一处要搜遍 27 个页面。→ 见 `01`、`02`
2. **半成品状态**：音乐页被砍到只剩搜索（用户自己的音乐库没地方看）、影视库是列表行而不是海报墙、
   设置页只有主题设置、源健康面板只有一列状态。→ 见 `02`、`03`、`04`
3. **协作无规范**：多个 Agent 并行改同一个仓库，没有分支策略、没有文件归属、没有验收标准，
   靠 `docs/progress.md` 一份文档接力。→ 见 `05`、`07`

### 1.3 立刻会看到的 5 个具体现象

1. 访客打开网站，影视 / 音乐 / GitHub **全是空的**——因为线上资源 `is_public` 全是 `false`
   （技术上是"正确"的，产品上是"网站看起来像空的"）。→ `04`
2. 音乐页只有搜索框，**自己的音乐库消失了**。→ `02`
3. 影视库是列表行，**没有海报墙**，不像影视产品。→ `02`
4. 设置页只有主题切换，**改密码 / 看账号信息没地方去**。→ `02`
5. 源状态面板要翻"更多"下拉才能看到，且**只有管理员能看**。→ `03`

## 4. 建议的推进节奏（三批）

### 第一批：一致性 + 可见的完整性（约 1–2 周）

1. UI 设计令牌 + 统一页头/卡片/空态（`01`）
2. 音乐页收尾、影视库海报墙（`02`）
3. 公开/私密批量控制入口（`04`）

**上线判据**：随便点开 5 个页面，页头结构一致；访客能看到非空内容。

### 第二批：可靠性 + 体验（约 1–2 周）

4. 源定期探活 + 死链批量自愈（`03`）
5. 源健康面板增强（`03`）
6. 播放体验（记忆进度 / 选集 / 移动端）（`03`）
7. 编辑页骨架 + 设置页扩展（`02`）

**上线判据**：源挂掉能在面板上看到并自动避让；播放能续播。

### 第三批：扩展 + 工程（持续）

8. 画廊 / 时间线模块收尾（`06`）
9. 测试补齐 + 可观测性（`05`）

## 5. 怎么用这套文档（给站长的操作指引）

1. **想改什么** → 打开 `07-给执行Agent的提示词包.md`，找到对应那一节，**整段复制**发给 Agent。
2. **想知道为什么这么改** → 打开对应编号的文档看"现状 / 问题 / 建议 / 优先级"。

## 6. 关于"分支"这件事（先讲清楚，再看 `05`）

站长说"对分支不了解"，这里用最直白的话解释：

- **`main` 分支 = 正式版**。往 `main` 推代码，GitHub Actions 会**自动部署上线**，
  几分钟后网站就是新的。这就是为什么"改 GitHub 代码前端会实时更新"——是的，**会自动更新**。
- **分支 = 草稿本**。在分支上改，**不会影响线上**，改完确认没问题再合并进 `main`。
- **本轮的实际情况**：影音源修复就是在分支上做完、验证通过、再合并到 `main` 上线的
  （合并提交 `87e13f8`）。这就是**推荐做法**。

**给站长的推荐**（详见 `05` 第 6 节）：

| 改动类型 | 建议做法 |
| --- | --- |
| 小改（文案、单个样式、加一个源） | 直接在 `main` 上做，自动部署，快 |
| 中改（一个页面的重排） | 开分支做完合并，避免改到一半线上是坏的 |
| 大改（设计系统、新模块） | 开分支 + PR 预览，确认后再合并上线 |

## 7. 维护约定

- 本文件夹内**每份文档只讲一类事**，不合并成大杂烩（遵循 `~/AGENTS.md` 第 5.4 节）。
- 每次做完一批改进，**在对应文档里划掉已完成的条目**，并在 `docs/progress.md` 记一笔。
- 新增建议 → 放进对应编号文档；**不要新开编号**，除非是全新领域。
- 本文件夹由**站长指定的唯一 Agent** 维护，避免多 Agent 同时写（`~/AGENTS.md` 第 10 节零共享写入）。

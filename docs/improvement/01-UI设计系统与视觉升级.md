# 01 · UI 设计系统与视觉升级

> **这份文档解决什么**：让全站看起来像"同一个产品"，而不是二十多个页面各写各的。
> 重点是**统一页头、卡片、状态、表单、按钮、间距、字体**，并且**分批改、每批可独立上线可回退**。
>
> **写给谁看**：站长（不懂技术也能看懂每条建议要动哪个文件、值不值得做）+ 执行 Agent（照单施工）。
>
> **基线**：`frontend/src/styles/global.css`（5298 行）、`frontend/src/styles/graph-console.css`（170 行）、
> `frontend/src/components/`、`frontend/src/routes/`（27 个页面文件，共 5160 行）。
> **行号会随代码变动而漂移**，执行时请以文件名 + 类名/组件名定位。

---

## 0. 怎么用这份文档

1. 先看**第 1 节现状体检**，知道"乱在哪、乱到什么程度"（都是实测数字，不是印象）。
2. 再看**第 2–8 节规范**，那是"改成什么样"。
3. 最后看**第 9 节落地顺序**，按批次派活；每批都写了"上线判据"和"怎么回退"。
4. 每条建议都带 `优先级`（P0/P1/P2）与 `工作量`（小 <2h / 中 半天 / 大 1天+）。

**一条总原则**：**只做收敛，不推翻**。项目已有自己的"液态玻璃"视觉语言，`MovieView`
是全站视觉标杆。本轮**不引入任何 UI 框架、不换配色方向、不加第三套主题**。

## 2. 设计令牌（Design Token）

### 2.1 现状判断

令牌**已经存在**，问题不是"没有"，而是"没人用"。所以本节的建议是：
**补几个缺的、统一命名、把值调齐，然后强制新代码只用令牌**。不需要重造一套。

### 2.2 建议的令牌清单（在 `frontend/src/styles/global.css` 顶部 `:root` 内维护）

**① 颜色**（保留现有 9 个，新增 6 个）

| 令牌 | 建议值（白天主题） | 说明 |
| --- | --- | --- |

| `--border` | 保持现状 | 边框 |
| `--primary` / `--primary-contrast` | 保持现状 | 主色 / 主色上的文字 |
| `--danger` | 保持现状 | 危险操作 |
| `--success` | `#16a34a`（新增） | 目前只有兜底值，正式定义 |
| `--warn` | `#d97706`（新增） | 目前 toast 里硬编码，提到令牌 |

--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);      /* 保持 */

| 断点 | 含义 | 现状 |
| --- | --- | --- |
| `1280px` | 大屏内容上限（`.app-main max-width`） | 已有 |
| `1000px` | 侧栏收起（博客、GitHub 两栏变一栏） | 已有 |
| `920px` | 顶栏导航改横向滚动 | 已有 |

> 现有 18 种断点里，**768 / 760 / 720 / 660 / 640** 五个在表达同一件事。新代码只准用上表 5 个；
> 老代码**不必一次性全改**（风险高），在碰到哪个段落时顺手归一即可。

### 2.3 渐进式替换方法（重要，避免一次性大改）

1. **先补令牌，不改任何现有值**——把缺失的 `--success` / `--warn` / `--card-pad` / `--z-*` 加进 `:root`，
   这一步**零视觉变化、零风险**。
2. **补基础类**（第 3 节），新类内部只用令牌。
3. **逐文件替换**，一次只动一个页面，替换顺序：编辑页 → 管理页 → 列表页。
4. 每个文件改完，用同一份"对照清单"自查（见第 9 节验收判据）。
5. **禁止**在同一个提交里既改令牌值又改 10 个页面的结构——出问题时无法判断是谁引起的。

- 优先级：**P0**（第 1 步）/ **P1**（第 3 步） ｜ 工作量：**中**

## 3. 组件规范

### 3.1 统一页头：把 `PageHeader` 升级为唯一入口

**目标**：除"沉浸式播放页"外，所有页面都必须有一个可识别的页头，且结构一致。

`components/PageHeader.jsx` 增加 `variant` 属性，覆盖三种真实场景：

| variant | 用于 | 结构 |
| --- | --- | --- |
| `list`（默认） | 列表页 / 工具页 | kicker + h1 + 副标题 + 读数条 + 标签栏 + 右侧操作 |
| `detail` | 详情页（影视 / 音乐 / 博客阅读） | 返回按钮 + 面包屑 + 标题 + 元信息行 + 右侧操作 |
| `bare` | 特殊页（`Login`、`404`） | 仅标题 + 副标题，居中，无读数条 |

**落地清单**（谁改成什么）：

| 页面 | 现状 | 改成 |
| --- | --- | --- |
| `routes/Github.jsx` | 无页头，直接两栏 | 顶部加 `variant="list"`，标题"GitHub 收藏" + 读数条（总数 / 已解读）+ 同步按钮放右侧操作区 |
| `routes/Graph.jsx` | `.gc-hud` 自成一套 | 保留 `.gc-hud` 作为"沉浸式控制台"（它是刻意做的仪表盘），但**页面顶部补一条返回/标题带**，并在文档里注明"这是有意为之的例外" |
| `routes/PostEdit.jsx` / `MovieEdit.jsx` / `MusicEdit.jsx` | `.toolbar` + 裸 `<h2>` | 统一换成 `PageHeader variant="detail"`（返回 + 标题"新建/编辑 xx" + 右侧保存/预览按钮） |
| `routes/PostView.jsx` | `.pv-hero` 自造 | 保留 `.pv-hero` 的**头图**（阅读页需要），但把"返回 + 分类徽章 + 标题 + 元信息"改成 `PageHeader variant="detail"` 的结构类名，保证字号/间距一致 |
| `routes/Login.jsx` | 裸 `<h1>` + 行内 style | `PageHeader variant="bare"` + 卡片包裹表单 |
| `app.jsx` 的 `NotFound` | 裸 `EmptyState` | `PageHeader variant="bare"` + `EmptyState`，并给一个"返回首页 / 去搜索"双按钮 |

## 4. 字体与排版

### 4.1 现状

- 自托管字体在 `frontend/public/fonts/`：`satoshi-400/500/700.woff2`、`newsreader-400/500.woff2`，
  声明在 `frontend/src/styles/fonts.css`（46 行，`font-display: swap`）。**无外部 CDN 依赖，这点很好，保持。**
- 三字体分工已写进 `:root` 注释：UI = Satoshi，Display = Newsreader，Mono = 等宽（kicker/数字/时间戳）。
- **已知坑**：Newsreader **只有 400 / 500 两档**，`global.css` 顶部注释明确写了"展示标题禁用 600+"，
  但全局 `h1 { font-weight: 700 }` 仍存在——一旦某个 `<h1>` 没被 `.page-head-text h1` 或 `.display` 覆盖，
  就会触发浏览器合成粗体，边缘发虚。

### 4.2 建议

1. **修掉字重冲突**（P0，小）：
   全局 `h1` 默认字重从 `700` 改为 `500`，并统一走 `.display`（`--font-display`）。
   凡是需要"更重"的标题，用无衬线（`--font-ui` + 600/650），**不要给 Newsreader 加粗**。
2. **字号阶梯落地**（P1，中）：按第 2.2 节 ⑤ 的令牌替换 245 处硬编码 `font-size`。
   优先替换高频值：`13px`→`--fs-sm`、`12px`→`--fs-caption`、`12.5px`→`--fs-caption`（或新增 `--fs-caption-lg`）、
   `11.5px`→`--fs-kicker`。
3. **中英文混排注意点**（P1，小）：
   - 中文行高比英文需要更松：正文 `line-height: 1.6`，中文为主的段落建议 `1.75`。
   - 中英文之间**不加空格**（由字体回退处理），但**数字与单位之间保持现有写法**，不要引入 JS 自动插空格。
   - `--track-ui: -0.02em` 只对拉丁字母明显；中文标题建议 `letter-spacing: 0`（现在部分中文标题吃到了 `-0.02em`，显得挤）。
   - 中文回退栈已有（`PingFang SC` / `Hiragino Sans GB` / `Microsoft YaHei`），保持；**不要**再引入新的中文字体文件。
4. **数字统一等宽**（P1，小）：读数条、时长、计数、时间戳统一 `font-variant-numeric: tabular-nums`
   （`.stat b` 已做，`.count` / `.result-time` / `.queue-time` / 热榜时间未做）。
5. **阅读宽度**：`--content-read: 780px` 已定义但只用在少数地方；
   `PostView` 正文、`PostEdit` 预览、`MusicLyrics` 歌词建议统一使用该宽度，避免"行长忽宽忽窄"。

- 优先级：**P0**（字重）/ **P1**（阶梯与混排） ｜ 工作量：**小 ~ 中**

### 5.1 现状评估

**两个具体冲突**：

1. `global.css` 里约 **26 条 `[data-theme='dark']` 规则**仍然存在（暗色已移除，永不生效）——
   其中 `.cs-dock`、`.cs-banner`、`.cs-search` 等还在引用，**留着会误导后续开发**。

1. **不做第三套主题**（P0，结论）。理由：每多一套主题，就要为它维护全部硬编码颜色
   （现在硬编码颜色已经不少），维护成本远大于收益。站长如果觉得"白天太亮"，正确做法是
   **调 `light` 的默认值**，而不是新增主题。
2. **删掉失效的暗色规则**（P2，小）：26 条 `[data-theme='dark']` 全部删除。
   `graph-console.css` 里的深色是"该页自身的视觉语言"，**不算主题**，保留但要在文件头注释里写清。
3. **修掉博客体系的主题漏点**（P1，小）：`.cs-dock button.on` 的颜色改为 `var(--cs)`，
   让底部工具栏跟随主题（现在素雅下是青绿，与整站不搭）。
4. **自定义配色白名单保持现状**（`frontend/src/lib/theme.jsx` 的 `THEME_VARS` 9 项）：
   不要把 `--success` / `--warn` 加进白名单——用户改坏语义色后，错误提示会变得不可识别。
5. **主题切换过渡**：`global.css` 已有"切换主题时不要啪地跳变"的处理，保持；
   但要注意 `prefers-reduced-motion` 下应禁用该过渡（现在部分过渡未覆盖）。

- 优先级：**P0**（不加第三套）/ **P1**（修漏点）/ **P2**（清死规则） ｜ 工作量：**小**

| 页头在移动端堆叠后，操作按钮与标题争宽 | `.page-head-main` | ≤720px 强制 `flex-direction: column; align-items: flex-start`，操作区换行 | P1 | 小 |

- 优先级：**P0**（安全区）/ **P1**（触控、堆叠） ｜ 工作量：**小 ~ 中**

## 9. 落地顺序（4 批，每批可独立上线、可回退）

> 通用回退方式：**每批一个提交**，出问题直接 `git revert <该提交>`。
> 每批改完都要跑：`cd frontend && npm run build`，并在 1440 / 1024 / 390 三个宽度、
> 白天 / 素雅两套主题下各看一眼。

### 批次 1 · 令牌与基础类（风险：低）

**做什么**

1. `global.css` `:root` 补齐令牌：`--success` / `--warn` / `--info` / `--primary-soft` /
   `--danger-soft` / `--surface-hover` / `--card-pad` / `--field-gap` / `--fs-display` /
   `--fs-metric` / `--fs-chip` / `--radius-xs` / `--z-base` / `--z-raised` / `--z-header` / `--z-overlay` / `--z-progress`。
2. 新增基础类：`.card--pad` / `.card--flush` / `.card--hover` / `.chip-row` / `.form-grid` /
   `.form-row` / `.field` / `.field-hint` / `.field-error` / `.form-actions` / `.btn--sm` / `.btn--lg` /
   `button.ghost` / 全局 `.icon-btn`。
3. **不改任何现有页面的结构**，只把 `pv-progress`(9999)、`pv-viewer`(500)、`pv-drawer`(400)、
   `cs-dock`(150) 四个魔法 `z-index` 换成新令牌（值等价，视觉不变）。
4. 删除 26 条失效的 `[data-theme='dark']` 规则（这是纯删除，零视觉变化）。

**上线判据**：`npm run build` 通过；逐页对照截图**没有任何视觉变化**。

**为什么先做这批**：它零风险，但让后面三批"有工具可用"。

### 批次 2 · 页头 + 卡片 + 状态（风险：中）

**做什么**

1. `components/PageHeader.jsx` 增加 `variant`，先给 `Github` / `PostEdit` / `MovieEdit` / `MusicEdit` / `Login` / 404 换页头。
2. 卡片：`Github` 换通用卡；`AdminUsers` / `Backup` / `Settings` / `ThemeCustomizer` 的行内 padding 换 `.card--pad`。
3. 状态：`app.jsx` 两处 `center-box`、`MusicLyrics` 裸文本改 `LoadingState`。
4. 移动端安全区 + 页头 ≤720px 堆叠。

**上线判据**：随机点开 8 个页面，页头结构一致；加载时**不再出现"正在载入…"纯文本**。

**回退**：本批改动集中在 6–8 个文件，单独提交即可整体回退。

### 批次 3 · 表单骨架 + 设置页（风险：中）

**做什么**

1. 新增 `components/FormShell.jsx`，`PostEdit` / `MovieEdit` / `MusicEdit` / `Backup` 接入。
2. `routes/Settings.jsx`（现仅 20 行）扩为偏好中心骨架：
   主题（现有 `ThemeCustomizer`）+ 账号信息占位 + 通知偏好占位 + 危险区占位。
   ⚠️ **只做 UI 骨架与分区，不改后端**；具体功能是否要做由 `docs/improvement/04` 决定。
3. 按钮层级：`.ghost` 落到 `MovieView` 返回/编辑；`AdminUsers` 危险操作加 `.danger` + 二次确认。

**上线判据**：三个编辑页在 390px 宽下字段不溢出；保存按钮在移动端吸底可见。

### 批次 4 · 主题、动效、清理（风险：低）

**做什么**

1. 字体：全局 `h1` 字重 `700 → 500`（消除 Newsreader 合成粗体）。
2. 字号令牌替换（从高频值开始，允许分批）。
3. 动效：卡片倾斜加条件、按钮扫光只留 `.primary`、补齐 `prefers-reduced-motion`。
4. 清理：`.vod-head` / `.music-head` 残留 CSS、`Movies.jsx` 无效 `hot` 传参、
   `cs-dock button.on` 硬编码色改 `var(--cs)`。
5. `global.css` 拆分：**本批不做**。只新增一节注释"新增样式写在哪个分区"的规范。

**上线判据**：素雅主题下底部工具栏高亮色跟随主题；`prefers-reduced-motion` 开启后无持续动画。

### 关于 `global.css` 是否拆分（结论）

**暂不拆**。理由：5298 行虽然长，但已有约 60 个分区注释，可检索；拆分后
CSS 加载顺序、`!important`（现有 7 处）与同名覆盖关系都会变，回归风险大于收益。
替代方案：**加规范 + 加边界**——

- 在文件顶部写清"分区目录"（哪些类归哪一节）；
- 新增样式必须落在对应分区，禁止在文件末尾追加；
- 后续若真要拆，按"主题变量 / 基础类 / 布局 / 组件 / 页面"五层拆，且一次只拆一层。

- 优先级：**P2** ｜ 工作量：**大**（本轮不做）

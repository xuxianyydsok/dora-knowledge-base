**需求要点**

- 站长能把网址粘进去，自动抓站点的标题 / 图标 / 简介。
- **先放这两个**（用户指定）：
  - 新浪财经 7×24 直播：`https://finance.sina.com.cn/7x24/`

- 这两个站**只做导航链接，不抓内容**（用户明确：「那个七乘二十四小时那个不用抓了吧它本来就是
  更新的比较快的」「ai bot.cn 的那个网站，我只是让你看一下能否就是抓取到，我只是想试一下」）。

**技术调研结论（2026-10-12 已实测，供后续参考）**

| 站点 | 有无 RSS | 能否抓 | 说明 |
| --- | --- | --- | --- |
| `finance.sina.com.cn/7x24/` | 无 | 有隐藏 JSON 接口 | `zhibo.sina.com.cn/api/zhibo/feed?zhibo_id=152` 返回 JSON，数据在 `result.data.feed.list`。**更新极快（按分钟），不适合做 RSS**，只做导航链接 |
| `ai-bot.cn/daily-ai-news/` | 无（`/feed/` 已关闭：`Feed已关闭`） | 整页 HTML 可抓 | 日报是**一页天天更新**的长文（当日 64 万字节 HTML），没有按日期分档的存档页；新闻条目在 `.news-list > .news-item`，每条带 `<h2><a>` 和 `.news-time`。WordPress REST API 被挡（返回首页 HTML），但 `wp-sitemap.xml` 可读。**结论：技术上能解析成 RSS，但没必要**，做导航链接即可 |

## 5. 音乐：接会员账号（Cookie）取流 —— 解决 VIP 曲完整播放（2026-10-13 登记）

> **2026-10-13 附带修复**：探测到搜索阶段的**子请求超限**问题并已修复，
> 详见 `docs/progress.md` 当日条目「影视源：修掉『只有 3 条源』」。
> 结论：Cloudflare 免费版**单次调用**子请求上限是 50（实测），
> 而旧代码会对 40 多个动态源逐个发 `ac=list` 发现动漫类目，直接把配额吃满。

**用户原话**：「有会员的话，不过已经到期了，就是到时候你可以把这个加入待办清单。」

**要解决的问题**：QQ 音乐 / 网易云的 **VIP 版权曲**（周杰伦、陈奕迅、邓丽君等原唱），
未登录只能拿到 30~60 秒试听，或干脆 404。**这跟部署在云上还是本机无关**——
平台卡的是「账号权限」，不是 IP（已实测：同一首歌用家庭宽带 IP 和机房 IP 测，结果一样）。
App 里能完整听，是因为登录了会员账号。

**方案（待用户会员开通后实施）**：

1. 用户提供 QQ 音乐 / 网易云的**会员账号 Cookie**（存进 Worker secret，禁止写入仓库）。
2. 后端取流时带上 Cookie 请求官方接口，平台按「会员身份」放行，返回完整音轨。
3. **不受 IP 风控影响**（认账号不认 IP），可跑在 Cloudflare Worker 上，不需要买服务器。
4. Cookie 有效期通常数月，过期后用户重新贴一次即可。

**技术要点（已调研）**：

- QQ 音乐：`u.y.qq.com/cgi-bin/musicu.fcg` 的 `vkey.GetVkeyServer` 带会员 Cookie 可拿到 `purl`。
- 网易云：官方 `song/enhance/player/url` 带 Cookie 可拿高码率完整流。
- 存储：`wrangler secret put` 注入，读取时**不回显**（遵守 `~/AGENTS.md` 密钥规范）。

**风险提示（须向用户说明）**：这是**账号级授权**，属于个人自用范畴；
若站点公开对外提供 VIP 曲访问，存在版权风险。建议仅站长自用，或对访客不开放此路。

**当前替代方案（已上线）**：接入 QQ 音乐搜索（经 vkeys 中转）+ 「需会员」标注，
让用户**搜得到、看得见、知道哪首要会员**；能免费播的直接播，VIP 曲如实标注。

## 7. B 站曲目自动识别歌名 / 歌手 —— **已评估，决定不做**（2026-10-13）

**用户原话**：「我上传那个哔哩哔哩的那个链接，它能不能自己识别那个歌手和那个歌曲名啊？」

**评估结论：技术上做不到「自动」，且识别准确率不可靠，用户选择手动填。**

实测（用真实链接 `BV1zc411P7V3`）：

| 路径 | 结果 |
|---|---|
| 后端 Worker 去读 | ❌ **B 站的 API、首页、播放器页三个域名全部超时** —— 机房 IP 连不上 B 站 |
| 前端直接调 B 站 API | ❌ 被 CORS 拦（返回 403，无跨域许可头） |
| `<script>` 标签绕过 CORS | ❌ B 站 API 不支持 JSONP，且本站 CSP 是 `script-src 'self'` |

**用本机浏览器能读到**（标题 / UP 主 / 简介 / keywords 都能拿到），
但要把「歌名 + 歌手」从标题里准确提取出来并不可靠 —— 实测标题形如：

    在百万豪装录音棚大声听 东宫ost 余昭源&叶里《初见》【Hi-res】

歌名是《初见》、歌手是「余昭源&叶里」，但标题里混着「在百万豪装录音棚大声听」
「东宫ost」「【Hi-res】」等噪声；各 UP 主命名习惯差异极大（有的「歌名 - 歌手」，
有的「【歌手】歌名」，有的塞一堆 tag），规则化提取必然经常出错。

**决定（用户拍板）**：不做识别，**手动填歌名 + 歌手**。上传时本来就要填这两栏，
多花几秒但 100% 准确。

**如果将来想再试**，可选方向（都已验证过前提条件）：
- 前端「点一下识别」：由浏览器去取标题并预填，用户核对修改（前端能否读到
  B 站视频页 DOM 尚未验证，B 站可能有防抓取）
- 记住同一 UP 主的歌手：常发音乐类视频的 UP 主（如 `JLRS-LeoFM`）可自动带出

## 8. 首页轮播图：管理员端可上传图片 / 视频替换（2026-10-13 登记）

**用户原话**：「首页它不是有那些图片吗？我想实现能够在管理员端上传图片，
或者说一些视频来进行轮播图的替换，或者说那个视频的一个轮播图。」

**需求要点**

- 首页当前的轮播图（HeroCarousel）是**静态资源**（`frontend/public/hero/`），
  换一张图要改代码 + 重新构建部署。
- 目标：站长在管理员端就能上传图片 / 视频，直接替换首页轮播内容，不用改代码。
- 支持**视频轮播**（不只图片）。

**开工前要确认的**

- 存哪：复用现有 R2 桶（`knowledge-base-assets`）还是新建前缀（如 `hero/`）？
- 与图展的关系：图展已有「静态图片 + 动态壁纸」两套上传与策展流程
  （见 `docs/gallery-timeline.md`），首页轮播是否可以**直接复用图展的素材**
  （站长在图展里策展，首页挑其中的几张）？这样不用重复做一套上传。
- 视频的自动播放策略：浏览器会拦截带声音的自动播放，首页轮播视频应**静音 + 循环**。
- 首屏性能：轮播图是 LCP 元素，上传的视频要限制体积（比如 ≤ 10MB），
  否则首屏会很慢。

**当前状态**：✅ **已完成（2026-10-13）**，见 `docs/progress.md` 2.36 与
`docs/api.md`「首页轮播 Hero Slides」。

**最终采纳的做法**（与上面「开工前要确认的」逐条对照）：

- **存哪**：新建 Supabase 表 `hero_slides`，但**只存对图展素材的引用**，
  不重复存文件；R2 对象仍归图展的 `assets` / `wallpapers` 两张表管
  （外键 `on delete cascade`，删素材时首页引用自动消失）。
- **与图展的关系**：**直接复用图展素材**。站长在图展页的「首页轮播」抽屉里
  从已上传的图片 / 动态壁纸中挑选，不再单独做一套上传。
- **视频策略**：静音 + 循环自动播；另给一个「有声音」开关（关掉静音后浏览器
  会拦自动播放，访客点喇叭按钮即可开声）。观众端轮播条上也有喇叭开关。
- **体积**：按用户要求**暂不限制**。

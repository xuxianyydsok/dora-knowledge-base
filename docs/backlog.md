## 1. 音乐：管理员上传本地歌曲（2026-10-12 登记）

**用户原话**：「我只会把我下载的歌曲给到，也就是上传到」「我肯定要手动填几个字的，
就比如说它的歌名，还有那个它的歌手是谁，谁唱了这首歌，就提供这两部分的内容。」

**需求要点**

- 访客 / 未登录用户**不能**手动录入音乐（现在 `/music/new` 页面对所有登录用户开放，要收紧）。
- 管理员在后台**直接上传音频文件**（不是粘第三方直链），存到 R2。
- 上传后**自动刮削**歌手、专辑、封面：
  - 优先读音频文件自带的 ID3 / Vorbis 标签（歌名、歌手、专辑、内嵌封面）；
  - 标签缺失时，用管理员填的「歌名 + 歌手」去匹配元数据（现有 `lib/metadb.js` / `lib/fetchers.js` 已有能力）；
  - 封面要高清。
- 歌词自动配好；**繁体中文要转简体**（用户明确反馈「有些时候搜出来的歌词展现的是繁体中文，这一点需要改正」）。
- 管理员只填两栏：**歌名 + 歌手**，其余自动补全。

**实现要点（已调研）**

- 后端：`backend/src/routes/music.js` 的 `createMusic` 现在只接受 JSON + 直链；
  上传要新增 multipart 路由，参考 `routes/assets.js`（图片）与 `routes/books.js`（电子书，含分片）。
- R2 绑定已有：`env.R2_BUCKET`（桶 `knowledge-base-assets`）。
- 音频直链可用 `GET /api/music/:id/stream` 之类的路径回源，避免把 R2 暴露成公开桶。
- 权限：`routes/music.js` 用的是 `requireAuth`，上传路由要改成 `requireAdmin`。

**待用户确认**：无需再确认，用户已给出「只填歌名 + 歌手」的答复，可直接开工。

## 2. 网址导航（2026-10-12 登记）

**用户原话**：「到时候做一个就是利用 cloudflare 做一个那个网址导航的那个东西然后把那个网址粘贴进去」

**需求要点**

- 用 Cloudflare 做（Pages / Workers，不用服务器）。
- 站长能把网址粘进去，自动抓站点的标题 / 图标 / 简介。
- **先放这两个**（用户指定）：
  - 新浪财经 7×24 直播：`https://finance.sina.com.cn/7x24/`
  - AI 工具集每日 AI 资讯：`https://ai-bot.cn/daily-ai-news/`
- 这两个站**只做导航链接，不抓内容**（用户明确：「那个七乘二十四小时那个不用抓了吧它本来就是
  更新的比较快的」「ai bot.cn 的那个网站，我只是让你看一下能否就是抓取到，我只是想试一下」）。

**技术调研结论（2026-10-12 已实测，供后续参考）**

| 站点 | 有无 RSS | 能否抓 | 说明 |
| --- | --- | --- | --- |
| `finance.sina.com.cn/7x24/` | 无 | 有隐藏 JSON 接口 | `zhibo.sina.com.cn/api/zhibo/feed?zhibo_id=152` 返回 JSON，数据在 `result.data.feed.list`。**更新极快（按分钟），不适合做 RSS**，只做导航链接 |
| `ai-bot.cn/daily-ai-news/` | 无（`/feed/` 已关闭：`Feed已关闭`） | 整页 HTML 可抓 | 日报是**一页天天更新**的长文（当日 64 万字节 HTML），没有按日期分档的存档页；新闻条目在 `.news-list > .news-item`，每条带 `<h2><a>` 和 `.news-time`。WordPress REST API 被挡（返回首页 HTML），但 `wp-sitemap.xml` 可读。**结论：技术上能解析成 RSS，但没必要**，做导航链接即可 |
